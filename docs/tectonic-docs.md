# Build Documentation (Tectonic version)

The **Build Documentation** workflow `tectonic-docs.yml` builds a standard Python documentation,
compiling the PDF with [Tectonic](https://tectonic-typesetting.github.io/) instead of a TeX Live
installation.

It is a sibling of [`uv-docs.yml`](uv-docs.md), not a replacement: both are maintained, and the
choice between them is per caller.

## Why Tectonic

`uv-docs.yml` installs ~500 MB of `texlive-*` packages through apt on every job. That is slow, and
when the runner-local apt mirror degrades it is the single most likely way for a documentation build
to hang.

Tectonic is one static binary (~10 MB) that downloads only the `.sty`, `.cls` and font files the
document actually references, from a pinned TeX Live bundle, and caches them. Consequences:

- The payload drops by two orders of magnitude, and what remains is cacheable — a TeX Live apt
  install is not.
- Builds are reproducible: the bundle is a pinned snapshot, so every caller and every run resolves
  the same package versions.
- `latexmk` disappears; Tectonic runs the rerun-to-convergence loop itself.
- The same engine is available locally with `brew install tectonic`, so a writer can check a PDF
  without a multi-gigabyte MacTeX installation and without pushing to CI.

Measured on this repository: cold cache ~75 s, warm cache ~2 s.

## Pre-requisites

1. The workflow expects a standard docs structure, as generated by the `sphinx-quickstart` script,
   in particular:
   1. A `docs` folder in the root of the project. This can be overridden with the `docs-folder` input.
   2. A `docs/Makefile`. If modified from the default, it must support the `html` and `latex`
      targets. Note `latex`, not `latexpdf`: the workflow compiles the generated sources itself.
      The stock `sphinx-quickstart` Makefile already supports both through its catch-all rule.
   3. A `docs/_build` folder with the build output, including an `html` folder and a `latex` folder,
      results of the `html` and `latex` build targets.
   4. A `pyproject.toml` file in the `docs` folder with the project name, version and dependencies.
2. Two settings in `docs/conf.py`:

   ```python
   latex_engine = "xelatex"
   latex_elements = {
       "sphinxsetup": "iconpackage=none",
       ...
   }
   ```

   Both are required — see **Caller requirements** below.

## Operation

The workflow will build two artifacts:

1. `documentation-<project>-html-<version>` with the documentation in HTML format.
2. `documentation-<project>-pdf-<version>` with the documentation as a PDF file.

It uses the release version provided as input.

Inputs:

| Input              | Type    | Default    | Description                                                                                     |
| ------------------ | ------- | ---------- | ----------------------------------------------------------------------------------------------- |
| `version`          | string  | (required) | Version number for the documentation.                                                           |
| `pdf-name`         | string  | (required) | Name of the PDF file to generate.                                                               |
| `build-pdf`        | boolean | `true`     | Whether to build the PDF. Much faster when disabled.                                            |
| `docs-folder`      | string  | `docs`     | Path to the docs folder from the root of the project.                                           |
| `makefile`         | string  | `Makefile` | The makefile to use.                                                                            |
| `lfs`              | boolean | `false`    | Whether to pull LFS files.                                                                      |
| `submodules`       | string  | `'false'`  | Whether to pull git submodules (`false`, `true` or `recursive`).                                |
| `dependencies`     | string  | `''`       | Additional system (apt) dependencies, space separated.                                          |
| `tectonic-version` | string  | `0.17.0`   | The Tectonic release to install.                                                                |
| `timeout-minutes`  | number  | `30`       | Maximum duration of the build job. Raise it for genuinely long builds.                          |
| `env`              | string  | `''`       | Additional environment variables for the build steps, as newline separated `KEY=VALUE` pairs.   |
| `artifact-suffix`  | string  | `''`       | Suffix appended to the uploaded HTML artifact name and the PDF filename, to distinguish builds. |

The provided version will be written in a `.version` file at the root of the repository.
You may/should use it to determine the version of the project/documentation.

Example:

```yaml
jobs:
  version:
    uses: nxlabs-ch/shared-workflows/.github/workflows/version.yml@main

  build-documentation:
    needs: version
    uses: nxlabs-ch/shared-workflows/.github/workflows/tectonic-docs.yml@main
    with:
      version: ${{ needs.version.outputs.version }}
      pdf-name: "User-Manual.pdf"
```

Note: the PDF name will be changed to add the version number, e.g. `User-Manual-1.0.0.pdf`.

## Caller requirements

### `latex_engine = "xelatex"`

Tectonic is a XeTeX engine. Feeding it the pdflatex-targeted sources Sphinx generates by default
*appears* to work — a PDF comes out — but every non-ASCII glyph is silently dropped, with
`Missing character: There is no … in font ec-qtmr` reported as a warning rather than an error.
Ellipses and curly quotes simply vanish.

Because a green build would otherwise hide this, the workflow checks the generated `.tex` for
`fontspec`, which Sphinx only emits for xelatex, and fails the build if it is absent. It also raises
a warning annotation if Tectonic reports any missing character.

If, as in this repository, the same `conf.py` has to serve both this workflow and `uv-docs.yml`,
override the engine in the Makefile target instead:

```make
latex:
	uv run sphinx-build -M latex . $(BUILDDIR) -D latex_engine=xelatex
```

### `sphinxsetup: iconpackage=none`

Since 7.4, Sphinx decorates admonition titles with FontAwesome icons if `fontawesome5.sty` is
available. Tectonic's bundle ships that file but not the `expl3.sty` it requires, which is a hard
error (`the XeTeX engine had an unrecoverable error`). Setting `iconpackage=none` disables the
decoration and fixes it.

### Fonts

No font package is needed. Sphinx's xelatex default is `\setmainfont{FreeSerif}`, and Tectonic
resolves `FreeSerif.otf`, `FreeSans.otf` and `FreeMono.otf` from its own bundle — no apt package, no
fontconfig dependency, no `fontpkg` override.

Note the PDF will not look identical to one produced by `uv-docs.yml`: that one uses pdflatex with
the TeX Gyre fonts. Expect visibly different type, not just metric noise. For customer-facing
documents, diff a before/after PDF before switching, or set `fontpkg` explicitly to keep the current
typeface.

## Caching

Tectonic's resolved packages are cached with `actions/cache`, keyed on the runner OS, the pinned
Tectonic version and a hash of `conf.py` — the file that determines which LaTeX packages the
document pulls in. A key miss still restores the most recent bundle for the same Tectonic version
through `restore-keys`, so a `conf.py` edit refreshes the cache instead of refetching it from
scratch.

The cache directory is pinned explicitly through `TECTONIC_CACHE_DIR`; Tectonic's default location
is platform dependent.

A cold cache still needs network access, so the failure mode is shrunk rather than eliminated —
which is why the job keeps a `timeout-minutes`.

## Local builds

```bash
brew install tectonic
make -C docs latex
tectonic -X compile docs/_build/latex/<name>.tex --outdir docs/_build/latex
```

Using the same engine locally and in CI removes a class of "renders on my machine, breaks in CI"
problems that a local MacTeX / CI TeX Live split quietly creates.
